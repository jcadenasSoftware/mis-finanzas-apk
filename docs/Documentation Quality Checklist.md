# Documentation Quality Checklist

**Fecha:** 15 de agosto de 2026  
**Versión:** 1.0

---

Use this checklist before marking any Xpendz document as complete.

## Content

- [ ] Explains **what** the topic is
- [ ] Explains **why** it exists
- [ ] Explains **how** it works
- [ ] Avoids implementation details when possible
- [ ] Uses simple, human-readable language

## Structure

- [ ] Has title with version and date
- [ ] Has clear sections
- [ ] Includes `Related Documents` section
- [ ] Includes `Module Health` section for module docs
- [ ] Includes `Glossary` terms when needed

## Visuals

- [ ] Contains Mermaid diagrams when they improve understanding
- [ ] Tables are used for structured comparisons
- [ ] Diagrams are described in nearby text

## Completeness

- [ ] Lists dependencies (incoming, outgoing, shared)
- [ ] Lists risks
- [ ] Lists technical debt
- [ ] Lists future improvements
- [ ] Identifies architectural inferences explicitly

## Consistency

- [ ] Terminology matches [Glossary](00_Project/Glossary.md)
- [ ] Links are valid and relative
- [ ] Follows [Documentation Standards](00_Project/Documentation%20Standards.md)
- [ ] No duplicated information with other docs
- [ ] Markdown formatting is consistent

## Maintenance

- [ ] Document is dated
- [ ] Version is explicit
- [ ] Next review date is noted for module docs
- [ ] ADR status is clear
