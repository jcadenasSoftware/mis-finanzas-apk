# Xpendz Android - Quality Assurance

Esta carpeta contiene la documentación relacionada con aseguramiento de calidad, mantenimiento técnico y estabilidad del proyecto Android Xpendz.

## Estructura de carpetas

### `Technical Maintenance/`
Registros de sprints de mantenimiento técnico, limpieza de código, modernización de APIs y reducción de deuda técnica:
- Reportes de mantenimiento técnico
- Documentación de APIs deprecadas
- Registro de warnings eliminados y pendientes
- Historial de limpieza de código y recursos

### `Visual QA/` (Futura)
Documentación de control de calidad visual:
- Checklists de validación visual
- Reportes de regresiones visuales
- Validación de temas (Light/Dark)
- Pruebas de consistencia de UI

### `Accessibility/` (Futura)
Documentación de accesibilidad:
- Auditorías de accesibilidad
- Reportes de contraste y legibilidad
- Validación de lectores de pantalla
- Guías de cumplimiento WCAG

### `Regression Reports/` (Futura)
Registros de pruebas de regresión:
- Reportes de pruebas funcionales
- Historial de bugs encontrados y corregidos
- Validación de flujos críticos
- Métricas de estabilidad

### `Release Readiness/` (Futura)
Documentación de preparación para releases:
- Checklists de pre-release
- Reportes de validación final
- Historial de versiones y cambios
- Métricas de calidad por versión

## Principio fundamental

**Todas las actividades de calidad deben quedar documentadas en la carpeta correspondiente.**

Esto incluye pero no se limita a:
- Sprints de mantenimiento técnico
- Correcciones de APIs deprecadas
- Limpieza de código y recursos
- Validaciones visuales y funcionales
- Auditorías de accesibilidad
- Pruebas de regresión
- Preparación de releases

## Mantenimiento

La documentación de calidad debe mantenerse actualizada en sincronía con los ciclos de desarrollo. Cada sprint de mantenimiento, corrección de calidad o validación debe reflejarse en esta estructura.
